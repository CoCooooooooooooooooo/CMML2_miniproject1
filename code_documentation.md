# Code Documentation: Aldehyde-Metabolising Enzyme Batch Docking Pipeline

**Project:** Miniproject 1 — Protein & Small Molecule Interaction Analysis  
**System:** Five ALDH isoenzymes (A15–A19) + two ADH isoenzymes (B1–B2) × 60 aldehyde substrates  
**Pipeline:** DiffDock → PRODIGY → Distance Analysis → Contact & Extension Analysis

### Protein identity reference

| File label | UniProt | Gene | Full name | Family | Catalytic residue |
|---|---|---|---|---|---|
| A15 | P49419 | *ALDH7A1* | Aldehyde dehydrogenase 7A1 (Antiquitin) | ALDH | Cys330 |
| A16 | Q9H2A2 | *ALDH1A3* | Aldehyde dehydrogenase 1A3 (RALDH3) | ALDH | Cys287 |
| A17 | P49189 | *ALDH9A1* | Aldehyde dehydrogenase 9A1 | ALDH | Cys288 |
| A18 | Q8IZ83 | *ALDH16A1* | Aldehyde dehydrogenase 16A1 | ALDH | / (undefined) |
| A19 | P54886 | *ALDH6A1* | Aldehyde dehydrogenase 6A1 (MMSDH) | ALDH | Cys612 |
| B1 | P07327 | *ADH1A* | Alcohol dehydrogenase 1A | **ADH** | / (Zn²⁺-dependent) |
| B2 | P00325 | *ADH1B* | Alcohol dehydrogenase 1B | **ADH** | / (Zn²⁺-dependent) |

> B1 (ADH1A) and B2 (ADH1B) are alcohol dehydrogenases, not aldehyde dehydrogenases. They are included as functionally related comparators within the aldehyde metabolic axis. Because their catalytic mechanism relies on zinc coordination rather than a nucleophilic cysteine, distance-based validation is not applicable; binding assessment for B1 and B2 relies exclusively on ΔG.

## 3. Script 01 — `01_generate_csv.py`

### Purpose

Automatically scans the protein and ligand input directories and writes a `tasks.csv` file in the exact column format required by DiffDock's `inference.py` batch mode.

### Key logic

```
protein_dir/   →  scan all .pdb files  →  proteins list
ligand_dir/    →  scan all .sdf files  →  ligands list
                         ↓
        Cartesian product: every protein × every ligand
                         ↓
              Write tasks.csv (420 rows for 7×60)
```

### Configuration (top of file)

| Variable | Default | Description |
|---|---|---|
| `PROTEIN_DIR` | `/mnt/Coco/A15-B2` | Folder containing `.pdb` files |
| `LIGAND_DIR` | `/mnt/Coco/substrate` | Folder containing `.sdf` files |
| `OUTPUT_CSV` | `/mnt/Coco/tasks.csv` | Output path |

### Output: `tasks.csv`

| Column | Example | Description |
|---|---|---|
| `complex_name` | `A15_formaldehyde` | Unique identifier for each pair |
| `protein_path` | `/mnt/Coco/A15-B2/A15.pdb` | Absolute path to protein PDB |
| `ligand_description` | `/mnt/Coco/substrate/formaldehyde.sdf` | Absolute path to ligand SDF |
| `protein_sequence` | *(empty)* | Not used; left blank as DiffDock reads from PDB |

> **Note:** The initial CSV omitted the `complex_name` column, which caused a `KeyError` in DiffDock's `inference.py`. The corrected version with all four columns resolved this.

### Usage

```bash
conda activate diffdock
python 01_generate_csv.py
# Output: Generated 7 × 60 = 420 pairs
```

## 4. Script 02 — `02_run_diffdock_batch.sh`

### Purpose

Launches DiffDock batch inference as a background process using `nohup`, so the job continues running after the SSH session is closed.

### DiffDock parameters

| Parameter | Value | Description |
|---|---|---|
| `--inference_steps` | 20 | Total reverse diffusion steps |
| `--actual_steps` | 18 | Steps actually executed (2 reserved) |
| `--samples_per_complex` | 1 | Only the top-ranked pose is retained |
| `--batch_size` | 10 | Complexes processed per GPU batch |
| `--no_final_step_noise` | flag | Disables noise at the last step for cleaner output poses |

### DiffDock output structure

After completion, each complex produces a subdirectory:

```
diffdock_results/
  A15_formaldehyde/
      rank1_confidence0.38.sdf    ← best docked pose (SDF format)
      rank2_confidence0.09.sdf
      ...
```

The confidence score in the filename corresponds to DiffDock's internal model confidence (higher = more confident). Only `rank1*.sdf` is used in downstream analysis.

### Monitoring and control

```bash
# Monitor progress in real time
tail -f /mnt/Coco/diffdock_run.log

# Count completed complexes
ls /mnt/Coco/diffdock_results | wc -l

# Stop the job
kill <PID>
```

### Usage

```bash
conda activate diffdock
bash 02_run_diffdock_batch.sh
# Output: DiffDock running in background — PID: XXXX
```

## 5. Script 03 — `03_pymol_batch_merge.py`

### Purpose

Uses PyMOL's Python API in headless (command-line) mode to merge each receptor PDB with its docked ligand SDF into a single combined PDB file.

> **Important note:** This script was **not used in the main analysis pipeline**. DiffDock outputs the receptor as `complex.pdb` and the ligand as `rank1.sdf` in separate files. Scripts 04 and 05 read these two files independently without needing a merged PDB, making this merging step redundant. The script is included here for completeness and for visualisation purposes in PyMOL.

### What it does

1. Iterates over all subdirectories in `diffdock_results/`
2. Loads the protein PDB and ligand SDF into PyMOL separately
3. Renames the ligand residue to `LIG` on chain `B` and the receptor to chain `A`
4. Saves the combined object as a single PDB file

### Usage (if required)

```bash
pymol -c 03_pymol_batch_merge.py
```

### Output

```
merged_structures/
  A15_formaldehyde_merged.pdb
  A15_acetaldehyde_merged.pdb
  ...
```

## 6. Script 04 — `04_batch_prodigy.py`

### Purpose

Calculates the binding free energy (ΔG, kcal/mol) for all successfully docked complexes using `prodigy_lig`. This script handles the SDF→PDB conversion internally, so no prior merging step is required.

### Key logic

```
For each complex_dir in diffdock_results/:
    1. Find rank1*.sdf  (ligand)
    2. Find matching protein .pdb from protein_dir/
    3. Convert SDF atom coordinates → HETATM PDB lines  [sdf_to_hetatm_lines()]
    4. Merge receptor ATOM lines + ligand HETATM lines → complex_merged.pdb
    5. Call: prodigy_lig -c A B:LIG -i complex_merged.pdb
    6. Parse ΔG from stdout (first float in range −30 to +5)
    7. Append {complex_name, dG_kcal_mol, status} to results list
Save → prodigy_results.csv
```

### SDF to HETATM conversion

The `sdf_to_hetatm_lines()` function is a minimal built-in converter that reads the atom block of the SDF V2000 format (lines 5 onward, up to `n_atoms`). It extracts X, Y, Z coordinates and element symbols, then formats them as valid PDB `HETATM` records. This avoids a dependency on RDKit for the merge step.

### PRODIGY ΔG parsing

`prodigy_lig` output format:

```
complex_name   -6.34
```

The parser scans each token for the first float value in the range `(−30, +5)`, which reliably captures the ΔG without being sensitive to output formatting changes.

### Configuration

| Variable | Default | Description |
|---|---|---|
| `RESULTS_DIR` | `/mnt/Coco/diffdock_results` | DiffDock output folder |
| `PROTEIN_DIR` | `/mnt/Coco/A15-B2` | Original protein PDBs |
| `OUTPUT_CSV` | `/mnt/Coco/prodigy_results.csv` | Output path |
| `PRODIGY_CHAIN` | `A` | Receptor chain label |
| `LIGAND_CHAIN` | `B` | Ligand chain label |

### Output: `prodigy_results.csv`

| Column | Type | Description |
|---|---|---|
| `complex_name` | str | e.g. `A15_formaldehyde` |
| `dG_kcal_mol` | float / NaN | Binding free energy (kcal/mol) |
| `status` | str | `OK`, `no_sdf`, `no_protein`, `merge_failed`, `prodigy_failed` |

### Usage

```bash
conda activate diffdock
python 04_batch_prodigy.py
```

## 7. Script 05 — `05_calculate_distances.py`

### Purpose

Calculates the 3D Euclidean distance between the catalytic Cysteine Sγ (SG) atom of each enzyme and the aldehyde carbon (C=O) of the best-ranked docked pose. A distance ≤ 5 Å is used as the threshold for a potentially productive binding pose.

This analysis applies only to proteins with a defined catalytic cysteine: **ALDH7A1 (A15), ALDH1A3 (A16), ALDH9A1 (A17), and ALDH6A1 (A19)**. ALDH16A1 (A18) is excluded because its catalytic cysteine is not unambiguously defined in available structures. ADH1A (B1) and ADH1B (B2) are excluded because they use a zinc-dependent mechanism with no nucleophilic cysteine — distance analysis is conceptually inapplicable to these proteins.

### Catalytic Cys mapping

The script reads `Catalytic_Cys_positions.xlsx` (provided by the instructor), which contains:

| Protein label | Gene | Cys annotation | Reason if skipped |
|---|---|---|---|
| A15 | ALDH7A1 | Cys330 | — |
| A16 | ALDH1A3 | Cys287 | — |
| A17 | ALDH9A1 | Cys288 | — |
| A19 | ALDH6A1 | Cys612 | — |
| A18 | ALDH16A1 | / | Catalytic Cys undefined in available structure |
| B1 | ADH1A | / | Zn²⁺-dependent mechanism; no catalytic Cys |
| B2 | ADH1B | / | Zn²⁺-dependent mechanism; no catalytic Cys |

Entries annotated as `/` are skipped for distance analysis. For A18, the skip is structural; for B1 and B2, it is mechanistic. All three are assessed by ΔG only.

### Aldehyde carbon identification

The `find_aldehyde_carbon_sdf()` function identifies the aldehyde carbon from the SDF atom block using the following logic:

```
For each carbon atom C in ligand:
    oxygen_neighbours = atoms of type O within 1.6 Å of C
    IF len(oxygen_neighbours) == 1:
        O = that oxygen
        IF O has no other heavy-atom neighbours within 1.6 Å:
            → C is the aldehyde carbon (terminal C=O)

Fallback (if no candidate found):
    → Return the carbon atom closest to any oxygen
```

This approach works robustly for all straight-chain and branched aliphatic aldehydes.

### Distance calculation

```python
distance = np.linalg.norm(cys_sg_coords - aldehyde_c_coords)
```

where `cys_sg_coords` is the XYZ position of the `SG` atom of the catalytic Cys residue, read directly from the original protein PDB via `parse_pdb_atoms()`.

### Configuration

| Variable | Default | Description |
|---|---|---|
| `RESULTS_DIR` | `/mnt/Coco/diffdock_results` | DiffDock output folder |
| `PROTEIN_DIR` | `/mnt/Coco/A15-B2` | Protein PDB files |
| `CYS_TABLE` | `Catalytic_Cys_positions.xlsx` | Instructor spreadsheet |
| `OUTPUT_CSV` | `/mnt/Coco/distance_results.csv` | Output path |
| `DISTANCE_THRESHOLD` | `5.0` | Å cutoff for productive binding |

### Output: `distance_results.csv`

| Column | Type | Description |
|---|---|---|
| `complex_name` | str | e.g. `A15_formaldehyde` |
| `protein` | str | Protein label (e.g. `A15`) |
| `ligand` | str | Ligand name (e.g. `formaldehyde`) |
| `cys_residue` | str | e.g. `Cys330`, or `/` if not applicable |
| `distance_A` | float / NaN | Cys SG – aldehyde C distance (Å) |
| `within_5A` | bool / NaN | `True` if distance ≤ 5.0 Å |
| `status` | str | `OK`, `no_cys`, `no_sdf`, `cys_sg_missing`, etc. |

### Usage

```bash
conda activate diffdock
python 05_calculate_distances.py
```

## 8. Script 06 — `06_extension_contact_analysis.py`

### Purpose

Extension analysis serving as the third interaction strength metric alongside ΔG and Cys–aldehyde distance. For every docked complex, the script counts protein–ligand heavy-atom contacts within 5 Å and classifies them by chemical interaction type. Results are merged with the existing ΔG and distance data to produce a unified three-metric table. For the straight-chain aliphatic aldehyde subset (C1–C16), the script additionally visualises how all three metrics vary with carbon chain length across all seven proteins.

### Key logic

```
For each complex folder in diffdock_results/:
    1. Parse protein heavy atoms from complex.pdb      [parse_pdb_atoms()]
    2. Parse ligand heavy atoms from rank1.sdf         [parse_sdf_atoms()]
    3. Vectorised pairwise distance calculation        (NumPy broadcasting)
    4. Count pairs within 5 Å; classify by atom type  [count_contacts()]
    5. Merge with prodigy_results.csv  (ΔG)
    6. Merge with cys_aldehyde_distances.csv  (distance)
    7. Map substrate name → carbon chain length        (ALIPHATIC_MAP)
Save → contact_results.csv
Generate → 3 PNG figures
```

### Contact type classification

Each protein–ligand heavy-atom pair within 5 Å is assigned to one of the following categories:

| Type | Atom pair | Chemical meaning |
|---|---|---|
| `CC` / `hydrophobic` | C – C | Hydrophobic interaction |
| `CO` | C – O | Carbon–oxygen contact |
| `CN` | C – N | Carbon–nitrogen contact |
| `SC` | S – C | Sulfur–carbon (catalytic site) |
| `polar` | N/O/S – N/O/S | Polar / hydrogen-bond capable contact |

Hydrogen atoms are excluded from all counts.

### Folder name parsing

DiffDock output folders follow two naming conventions due to re-runs with updated protein structures. The `PREFIX_MAP` dictionary handles both:

| Folder prefix | Protein |
|---|---|
| `A15-new-ALDH7A1_` or `A15_` | A15 (ALDH7A1) |
| `A16_` | A16 (ALDH1A3) |
| `A17-new-ALDH9A1_` or `A17_` | A17 (ALDH9A1) |
| `A18_` | A18 (ALDH16A1) |
| `A19_` | A19 (ALDH6A1) |
| `B1_` | B1 (ADH1A) |
| `B2_` | B2 (ADH1B) |

Substrate name is extracted from the trailing segment after the numeric index: `A15-new-ALDH7A1_6_hexanal` → `hexanal`.

### Substrate set (aliphatic subset)

13 straight-chain aliphatic aldehydes are mapped to carbon chain lengths for the extension figures. Note that C11, C13, and C15 are absent from the substrate set:

| Ligand name | Chain length |
|---|---|
| formaldehyde | C1 |
| acetaldehyde | C2 |
| propylaldehyde | C3 |
| butyraldehyde | C4 |
| amylaldehyde | C5 |
| hexanal | C6 |
| heptanal | C7 |
| octanaldehyde | C8 |
| nonanal | C9 |
| decanal | C10 |
| dodecanal | C12 |
| Tetradecanal | C14 |
| hexadecanal | C16 |

### Configuration

| Variable | Default | Description |
|---|---|---|
| `RESULTS_DIR` | `D:/…/diffdock_results` | DiffDock output root (update for server path) |
| `PRODIGY_CSV` | `prodigy_results.csv` | ΔG input file |
| `DISTANCE_CSV` | `cys_aldehyde_distances.csv` | Distance input file |
| `OUTPUT_CSV` | `contact_results.csv` | Output path |
| `CUTOFF` | `5.0` | Å; heavy-atom contact distance threshold |

### Output: `contact_results.csv`

| Column | Type | Description |
|---|---|---|
| `complex` | str | DiffDock folder name (e.g. `A15-new-ALDH7A1_1_formaldehyde`) |
| `protein` | str | Protein label (e.g. `A15`) |
| `substrate` | str | Ligand name (e.g. `formaldehyde`) |
| `total` | int | Total heavy-atom contacts ≤ 5 Å |
| `CC` | int | Carbon–carbon contacts |
| `CO` | int | Carbon–oxygen contacts |
| `CN` | int | Carbon–nitrogen contacts |
| `SC` | int | Sulfur–carbon contacts |
| `polar` | int | Polar contacts (N/O/S – N/O/S) |
| `hydrophobic` | int | Hydrophobic contacts (identical to CC) |
| `dG_kcal_mol` | float | Merged from `prodigy_results.csv` |
| `distance_A` | float / NaN | Merged from `cys_aldehyde_distances.csv` |
| `carbon_num` | int / NaN | Carbon chain length (aliphatic subset only) |

### Output figures

Three PNG figures are generated for the aliphatic aldehyde subset:

**`Fig_contact_vs_chain.png`** — 2×4 subplot grid. Each of the seven proteins occupies one panel showing total contact count vs. carbon chain length as a line plot, with a linear regression trendline and R² / p-value annotation. The eighth panel overlays all seven proteins for direct comparison.

**`Fig_three_metrics.png`** — 3×3 correlation scatter matrix comparing the three interaction metrics (total contact count, ΔG, Cys–aldehyde distance). Diagonal panels show histograms; off-diagonal panels show pairwise scatter plots coloured by protein, with an overall Pearson regression line and r / p annotation.

**`Fig_contact_type_stack.png`** — Stacked bar chart showing mean contact type composition (CC, CO, CN, SC, polar) at each carbon chain length, averaged across all seven proteins. Reveals how the chemical character of the binding interface shifts with substrate size.


Run the scripts in the following order on the GPU server:

```bash

# Step 1: Generate DiffDock input CSV

# Step 2: Run DiffDock batch docking (background; takes ~35 hours for 420 pairs)
bash 02_run_diffdock_batch.sh

# Step 3: (Optional) PyMOL structure visualisation only
# pymol -c 03_pymol_batch_merge.py

# Step 4: Calculate binding free energies
python 04_batch_prodigy.py

# Step 5: Calculate Cys–aldehyde distances
python 05_calculate_distances.py

# Step 6: Contact analysis and extension figures
python 06_extension_contact_analysis.py
# Requires prodigy_results.csv and cys_aldehyde_distances.csv in working directory
```
